## 2. Key findings (by criticality)

1. **Test-set tuning (M2) makes the absolute 74.8 unusable as a benchmark result.** The grid search picked the best configuration on the same split it reports. How large the effect is depends on the grid size and the test-set size. With n=1 (M1), there is no way to separate the method's effect from selection over the grid and seed luck.
2. **The baseline comparison is asymmetric.** One side is test-tuned and run fresh. The other side is a 2019 number copied from a paper. A +3.6-point gap across different pipelines is not a controlled effect.
3. **"Significant" is `[Y]`.** No test was run, n=1, and there is no variance. The wording should be removed or backed by evidence.
4. **Internal tension:** the ablation has 3 seeds and a std, but the headline has one run. Evidently the authors *could* run multiple seeds. The headline claim got less rigor than the secondary claim.
5. **What survives:** the evidence supports "the routing gate matters inside this architecture" (M5) far better than it supports "SparseRoute beats SOTA" (A1/A3/A5).

## 3. Missing card (what this format cannot show)

The abstract format shows one headline number. It cannot show:
- the size of the grid search, or the full distribution of test scores across it;
- seed variance for the headline;
- the baseline's performance under the authors' own pipeline;
- any post-2019 competitor;
- any negative results or other benchmarks they tried.

From the available evidence, the honest sketch is this: SparseRoute's true held-out gain over a re-run baseline is **unknown, bounded above by about 3.6**, and the ablation suggests that at least part of any gain comes from the routing gate.

## 4. Domain probe and conjunctions

- **Domain probe (step 7):** I wrote no scenarios. Scenarios I invented myself would be fiction. Probe list `supplied_by: none`, so no coverage claim goes above `[H]`. From ML-evaluation convention, the reviewer should ask about contamination between pretraining data and BenchQA, benchmark version drift since 2019, and compute parity.
- **Conjunction (step 8):** M2 × M5 can lower the ablation's validity. Hyperparameters tuned for the full model on the test set give the full model an advantage that the gate-less variant does not share. That could inflate the 2.1 points. Outcome: `unchecked`. The note doesn't say which HPs the ablation used.

## 5. Next steps (criticality × impact/effort)

1. **Retune on a validation split and report the test score once.** This is highest priority and moderate effort. It removes the M2 leak.
2. **Run the headline with at least 3 seeds and report mean ± std.** Low effort, since the ablation shows the infrastructure already exists.
3. **Re-run the baseline in the same codebase and eval script, with the same tuning budget.** This turns A3 into a controlled comparison.
4. **Either run a significance test (paired bootstrap over test items, or across seeds) or delete "significant".** This is a trivial edit.
5. **Search the post-2019 literature on BenchQA** before claiming SOTA.
6. **State the ablation's evaluation split and hyperparameter source**, and report the per-seed values.
