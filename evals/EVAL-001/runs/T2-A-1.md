# Claim review: SparseRoute abstract

## Headline claim
"SparseRoute improves BenchQA accuracy from 71.2 to 74.8, a significant improvement over the prior state of the art."

**Verdict: not supported as stated.** The methods note undercuts almost every part of it.

## Claim-by-claim

| # | Claim / component | Status | Why |
|---|---|---|---|
| A | SparseRoute scores 74.8 | **Weak / unreliable** | Single run (note 1): no variance estimate. Hyperparameters were tuned on the test split (note 2), so 74.8 is an optimistically biased, test-contaminated number, not a held-out estimate. |
| B | Baseline is 71.2 | **Weak for this comparison** | Copied from a 2019 paper (note 3), not re-run. Differences in preprocessing, evaluation script, compute budget, or tuning effort are uncontrolled. The baseline also got no test-set tuning, so the comparison is asymmetric. |
| C | +3.6 improvement is due to the method | **Not supported** | Confounded by test-set tuning (2), single-seed noise (1), and non-matched baseline conditions (3). Part or all of the gap could come from these. |
| D | Improvement is "significant" | **Unsupported** | No statistical test was run (note 4), and with one run there is no variance to test with. The word should be removed or a test run. |
| E | "Prior state of the art" | **Unverified** | The only comparison is to a 2019 baseline; nothing shows it was still SOTA. Newer methods may score higher. |
| F | Routing gate contributes about 2.1 points | **Supported (best-evidenced claim)** | Controlled ablation: same seeds, data, budget; 3 seeds each; std 0.3, so a 2.1 drop is about 7 std, clearly beyond seed noise. Caveats: only 3 seeds; if these runs use the test-tuned hyperparameters, the evaluation is still on the contaminated test split, so the absolute level is biased, though the within-study relative difference is more trustworthy. |
| G | Reproducibility (code, configs, eval script, exact commits) | **Supported (as described)** | Releasing everything with exact commits is strong; it lets others check A–F. It is only verifiable by actually visiting the repo, and it does not fix the design flaws. |

## Note an inconsistency
The ablation reports 3 seeds for the full model, while note 1 says all SparseRoute numbers come from one run. Either the headline 74.8 is one of those seeds (then why not report the 3-seed mean ± std?) or the two are separate runs. The authors should reconcile this.

## What would make the headline claim supportable
1. Tune hyperparameters on a validation split; evaluate once on test.
2. Re-run the baseline under the same pipeline, budget, and tuning procedure.
3. Report mean ± std over at least 3–5 seeds for both methods.
4. Run a significance test (e.g. paired bootstrap over test items, or a test across seeds) before using "significant".
5. Compare against current SOTA methods, not only the 2019 baseline.

## Bottom line
Supported: the routing-gate ablation effect (relative, within-study) and the release of code/configs. Not supported: the 74.8 vs 71.2 gain as evidence of method superiority, the "significant" label, and the "state of the art" framing.
