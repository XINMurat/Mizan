# Review: SparseRoute claims

## Headline claim: "improves BenchQA accuracy from 71.2 to 74.8, a significant improvement over prior SOTA" — NOT SUPPORTED

The 3.6-point gap cannot be credited to the method, for four independent reasons:

1. **Test-set tuning (note 2).** Learning rate and routing temperature were grid-searched on the BenchQA *test* split. That makes 74.8 an optimistically biased, best-of-grid score. It is not a held-out estimate. This problem alone is enough to invalidate the number. A validation split should have been used, with the test set evaluated once.
2. **Single run, no variance (note 1).** One training run gives no estimate of seed variance. The paper's own ablation shows std ≈ 0.3 across seeds for a closely related model, so the spread is real. Combined with the grid search, 74.8 may be the lucky maximum of many configurations and a single seed.
3. **Asymmetric, stale baseline (note 3).** The 71.2 figure is copied from a 2019 paper and was not re-run. Code, preprocessing, evaluation script, hardware and tuning effort may all differ. The baseline almost certainly did not get test-set tuning. The comparison is not like-for-like, so part or all of the gap could come from setup differences.
4. **"Significant" with no test (note 4).** No statistical test was run, so the word "significant" has no basis. "State of the art" is also not established. A 2019 baseline is unlikely to be the current SOTA, and no other recent methods are compared.

Who judged: the authors, on a split they tuned against, against a number they did not reproduce. No independent evaluation was done.

What a fix requires: tune on a validation split, run multiple seeds for both SparseRoute and a re-run baseline under the same pipeline, report mean ± std with a significance test, and compare against current strong methods.

## Ablation (note 5): routing gate contributes ~2.1 points — ADEQUATELY SUPPORTED (as an internal comparison)

This is the best-controlled claim in the paper:
- matched seeds, data and budget
- 3 seeds per arm
- std of 0.3, far smaller than the 2.1-point gap (roughly 7 std; clearly separated even with n=3)

Caveats:
- It supports only that the gate matters *within SparseRoute's configuration*.
- The hyperparameters were chosen on the test set, and presumably so was the evaluation. The absolute numbers stay inflated, and it is unclear whether the ablated model was re-tuned, which would bias toward the full model.
- The 3-seed full model also conflicts with note 1 ("all numbers ... from a single run"). The authors should reconcile this.
- The ablation does not rescue the headline claim against the baseline.

## Reproducibility (note 6): code, configs, eval script and exact commits released — SUPPORTED (as a factual/process claim)

This is verifiable and helps, but it adds nothing to the correctness of the results. Once released, the code will reproduce the test-tuned numbers too.

## Summary

| Claim | Verdict |
|---|---|
| 71.2 → 74.8 improvement due to SparseRoute | Not supported (test-set tuning, single run, unreproduced 2019 baseline) |
| "Significant" | Not supported (no test) |
| "Over prior state of the art" | Not supported (a 2019 baseline is not shown to be SOTA; the comparison is not like-for-like) |
| Routing gate contributes ~2 points | Supported internally, with caveats |
| Artifacts released for reproduction | Supported, but only as a process claim |
