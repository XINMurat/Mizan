# Claim review: SparseRoute

## Headline claim
"SparseRoute improves BenchQA accuracy from 71.2 to 74.8, a significant improvement over the prior state of the art."

**Verdict: Not supported as stated.** Only the claim that one run reached 74.8 on the test split, under test-tuned hyperparameters, is supported. The rest breaks down into four parts:

| Sub-claim | Status | Why |
|---|---|---|
| SparseRoute scores 74.8 | Weakly supported (a single observation) | One training run (note 1), so there is no variance estimate. Hyperparameters were grid-searched on the test split (note 2). That is test-set leakage, so 74.8 is an optimistically biased estimate and does not show how well the method generalizes. |
| Baseline is 71.2 | Unverified for comparison purposes | The number was copied from a 2019 paper and the baseline was not re-run (note 3). Differences in data version, preprocessing, eval script, compute budget and tuning effort are not controlled. The baseline also had no test-set tuning advantage, so the comparison is asymmetric. |
| +3.6 points is an "improvement" caused by the method | Not supported | The gap mixes the method effect with test-set tuning, run-to-run noise and a pipeline mismatch. None of these is separated out. |
| "Significant" | Unsupported | No statistical test was run (note 4) and n=1, so no test was even possible. The word should be removed or clearly marked as informal. |
| "Prior state of the art" | Unsupported | The only comparison is a 2019 baseline. Nothing shows it was still SOTA at submission time. |

## What is supported
- **The ablation (note 5): the routing gate contributes about 2.1 points within this setup.** This is the best-evidenced claim. It is a controlled comparison: same seeds, data and budget, 3 seeds per arm, std 0.3. A 2.1-point gap against std 0.3 is large relative to the noise. Caveats:
  - 3 seeds is few.
  - Whether the gate evaluation used test-tuned hyperparameters is not stated. If it did, the absolute numbers are inflated, although the relative gap is less affected.
  - This shows the gate matters *inside SparseRoute*. It does not show that SparseRoute beats the baseline.
  - The seeded ablation also contradicts note 1 ("all numbers from a single run"). The authors should reconcile the two.
- **Reproducibility (note 6):** Releasing the code, configs, eval script and per-table commits is a real strength. It supports "the results can be checked", but it does not make them valid.

## Needed to support the headline
1. Re-select hyperparameters on a validation split and report the test score once.
2. Run multiple seeds (for example 5 or more) and report mean ± std or CIs.
3. Re-run the baseline in the same pipeline with the same tuning budget.
4. Run an appropriate significance test (for example a paired bootstrap over test items plus a comparison across seeds), or drop "significant".
5. Compare against current SOTA, not only the 2019 baseline, or drop the SOTA claim.

## Bottom line
The abstract's main claim, a significant SOTA improvement from 71.2 to 74.8, is not supported: it rests on a single run, test-set tuning, an unreplicated baseline and no statistical test. The ablation is the one claim with credible support. Code release makes these problems checkable, but it does not fix them.
